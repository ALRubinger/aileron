## A 90-second demo

You ship the [Sentry MCP](https://mcp.sentry.dev/). This demo shows what changes one layer below — Sentry and Google composing in a single prompt, uniform install across both, kernel-level sandbox, credentials sealed locally.

## Try it yourself

Got it down to 3 commands.

```sh
brew install --cask ALRubinger/aileron/aileron
```

Installs Aileron on your system. You'll be prompted to create a passphrase for your new local Aileron vault, which is where we store credentials. Think 1Password or LastPass.

```sh
aileron pp add sentry
```

Pulls Sentry from the [PrintingPress](https://printingpress.dev/) catalog, runs Sentry's own CLI through Aileron's introspector, prompts you for `SENTRY_AUTH_TOKEN` token, and stores it sealed in the vault.

## What changes for Sentry

Sentry MCP and `getsentry/skills` are exactly right on the Sentry side. The limiting factor is the integration complexity. Linear, GitHub, and Notion each have a different auth flow. Each MCP process runs with full disk access. Configuring across Claude / Cursor / Codex / Goose means four parallel setups. So most orgs leave it to each engineer to figure out.

Aileron is what that work looks like when it's productized: one install per capability, sandboxed, credentials sealed locally, uniform across coding agents. For orgs adopting the general-bot pattern, Sentry's MCP isn't the friction. Standing up the rest of the bot around it is.
